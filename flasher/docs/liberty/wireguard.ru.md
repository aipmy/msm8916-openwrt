# WireGuard

[← Все инструкции Liberty](README.ru.md) · [English](wireguard.md) · **Русский**

Обычный WireGuard. Быстрый, компактный и легко узнаваемый в канале — оборудование
DPI опознаёт его без труда. Там, где это мешает, берите [AmneziaWG](amneziawg.ru.md):
та же настройка плюс маскировка.

## Где он находится

**Liberty → WireGuard** — это **только страница состояния**:

![Страница состояния WireGuard](../img/liberty/wireguard-status.png)

Здесь ничего не настраивается. Подключение — сетевой интерфейс, создаётся в
**Network → Interfaces**.

## Шаг 1 — создать интерфейс

**Network → Interfaces**, кнопка **Add new interface…** внизу списка.

![Диалог добавления интерфейса](../img/liberty/interfaces-add.png)

*① **Name** — `wg0`. ② **Protocol** — **WireGuard VPN**. ③ **Create interface**.*

| Поле | Значение |
|---|---|
| Name | `wg0` |
| Protocol | **WireGuard VPN** |

**Create interface** сразу открывает диалог самого интерфейса, и шаги 2–3 проходят
в нём. Если вы его закрыли, вернуться можно так: **Network → Interfaces** → строка
`wg0` → **Edit**.

## Шаг 2 — вписать ключи

В этом диалоге, вкладка **General Settings**:

- **Private Key** — ваш
- **Listen Port** — для клиента оставьте пустым
- **IP Addresses** — выданный вам адрес, например `10.0.0.2/24`

Если вы поднимаете собственный сервер и пары ключей ещё нет, рядом с приватным
ключом есть кнопка **Generate new key pair**.

## Шаг 3 — добавить узел

Вкладка **Peers** → кнопка **Add peer**. Откроется ещё один диалог:

| Поле | Значение | Примечание |
|---|---|---|
| Public Key | публичный ключ сервера | |
| Preshared Key | если используется | необязательно |
| **Allowed IPs** | `0.0.0.0/0` | **именно это отправляет в туннель весь трафик** |
| Route Allowed IPs | **включить** | создаёт маршруты по строке выше |
| Endpoint Host / Port | адрес и порт сервера | |
| Persistent Keep Alive | `25` | держит туннель живым за NAT |

При использовании IPv6 добавьте ещё `::/0`.

Затем **Save**, чтобы закрыть диалог, и **Save & Apply** внизу страницы Interfaces.

## Шаг 4 — пустить всё через туннель без утечек

Дальше по инструкции [Чтобы не текло: kill-switch и DNS](kill-switch.ru.md):
создайте зону `vpn` с интерфейсом `wg0` и переведите перенаправление `lan` с `wan`
на неё. Начинайте сразу с шага 2 — `wg0` уже интерфейс, шаг 1 не нужен.

`Allowed IPs = 0.0.0.0/0` — это утверждение о маршрутизации, а не гарантия. Оно
действует, пока интерфейс поднят; при падении туннеля маршрут уходит вместе с ним, и
трафик возвращается на модем, если firewall этого не запрещает.

## Проверка

**Liberty → WireGuard** перечисляет узлы и время последнего рукопожатия — **Latest
handshake**. WireGuard по своей природе молчалив: нет рукопожатия — нет и туннеля,
что бы ни показывало состояние интерфейса.

Частая причина отказа без внятной ошибки — часы. WireGuard отвергает рукопожатия,
когда стороны расходятся во времени. У донгла нет батарейки для часов, поэтому после
долгого простоя он может стартовать с неверной датой. Проверьте **Status →
Overview**.
